Copilot Usage Insights & Agent Adoption Platform — Design Document

POC Last updated: 2026-08-12  ·  Owner: TBD  ·  Source of truth: prompt.md · problem-statement.txt

1. Executive Summary

Adoption is one of the biggest barriers to realizing AI value. Leaders lack visibility into who is using AI agents, where adoption is lagging, and which interventions would increase value realization. Employees are often unaware of tools that could improve their productivity.

This platform delivers a generic, reusable, privacy-preserving mechanism that any AI agent repository can adopt to capture:

  1. Adoption & usage — derived from local VS Code Copilot debug logs, keyed to the user's ACF2 ID.
  2. Feedback signals — a delayed survey (default 14 days after first use) capturing sentiment, time saved, and barriers.
  3. Cost & efficiency insights — token efficiency, estimated cost, and intelligence-based token wastage (right-sizing model choice to task complexity).

All data lands in the organization's AWS workload account (the durable system of record for this POC) and powers an admin dashboard (org-wide adoption, cost, wastage, token-award eligibility) and a user dashboard (private, self-service coaching).

Non-goals (POC): no Copilot API key usage, no central storage of prompts/responses/source code, no cross-device reconciliation, and no disaster-recovery fallback store.

3. Key Design Decisions & Constraints

#DecisionRationale
D1AWS workload account is the durable system of record.Organization-approved storage; least-privilege, encrypted, append-only, idempotent.
D2No memory/DR fallback for the POC.Scope reduction; local queue + bounded-backoff retry is sufficient to demonstrate value.
D3One user = one device. ACF2 ID is the identity key.ACF2 IDs are already unique with an existing ACF2↔username map; no cross-device reconciliation needed.
D4Org hierarchy comes from Microsoft Teams.Enables admin filtering by org/team/role/BG/Division without inspecting prompts.
D5Only local telemetry already written by VS Code is used.No Copilot API key; no new data collection surface.
D6Privacy by default: exclude prompt/response/code/paths/args.Only numeric + metadata fields leave the device.
D7All cost/wastage are estimates/heuristics, clearly labeled.Avoids misuse as performance judgment; supports coaching, not discipline.
D8Explicit consent lifecycle keyed by ACF2 ID.Opt-in/opt-out, withdrawal, erasure, and audited re-identification.

4. Data Sources

Discovered locally under the platform-resolved VS Code user-data directory:

workspaceStorage/*/GitHub.copilot-chat/debug-logs/*/main.jsonl   # events
workspaceStorage/*/GitHub.copilot-chat/debug-logs/*/models.json  # pricing & capability
  • llm_request events → model, inputTokens, cachedTokens, outputTokens, ttft, dur, responseId, session ID, timestamp.
  • Agent debug-flow events → event type/timestamp, agent ID/name, skill ID/name, extension version, tool category/name, status, duration, retry/error category, edit/file-change count, workflow/session completion state.
  • models.json → model capability, tier, category, context limit, input/cache/output prices.

Log format and availability are treated as implementation-dependent; missing/unsupported logs are detected gracefully and reported via the data-quality panel.

5. Metrics & Insights

5.1 Estimated cost

5.2 Intelligence-based token wastage

Each turn is classified into a task-complexity tier using only privacy-safe signals (session depth, tool-call count/category, files affected, changed-file count, context size, multi-step behavior, retry/error counts — never prompt text). Each tier maps to a reference model of appropriate intelligence (e.g. Claude Opus 4.8 for the hardest tasks; low-cost/Auto for simple/repetitive tasks).

Each turn is labeled over_provisioned, right_sized, or under_provisioned.

5.3 Insight catalog

#InsightNotes / caveat
1Token efficiency (I/O ratio, cache-hit rate, non-cached context growth, cost, high-input/low-output turns)Observed telemetry.
2Wastage signals (expensive turns w/o outcome, repeats, context expansion)Heuristic; never "wasteful" as fact.
3Model recommendations (vs. compatible lower-cost models)Alternative latency/quality are counterfactual estimates.
4Model-need classification (likely justified / review opportunity / insufficient evidence)Never misconduct or performance judgment.
5Organizational classification (organizational vs personal_or_unknown)Allow-list on Git remote only; no prompt inspection.
6Agent-flow effectiveness (request→tool/edit/validation/completion rates, durations)Workflow signal, not productivity proof.
7Friction & recovery signals (retry loops, validation-fail→recover, interruptions)Diagnostic opportunity only.
8Outcome correlation (cost/latency/cache/tier vs. observed outcomes)Correlation ≠ causal value or time saved.
9Intelligence-based token wastage (§5.2)Configurable, counterfactual; not misuse proof.

13. Dashboards

13.1 Admin dashboard (administrator-only)

  • Global filters: Teams org hierarchy (org / team / role / BG / Division / region) and agent/skill — applied to every panel.
  • Adoption & feedback: active users, adoption/dormancy by team & agent, first-use & retention curves, feedback rollups (sentiment, time saved, top barriers) joined to usage.
  • Cost & efficiency: token/cost trend, cache efficiency, context-bloat patterns, model mix, savings opportunities, latency by model.
  • Justification & classification: justification distribution (drill-down to numeric evidence only), organizational vs personal_or_unknown.
  • Agent-flow: request→tool→edit→validation→completion funnel, tool reliability, retry-loop and recovery trends.
  • Token-wastage: wasted tokens/cost by tier, provisioning-label mix, top over-provisioned patterns.
  • Credit-eligibility (per user): credit consumed/remaining, wastage rate, right-sized ratio, cache-hit rate, outcome rates, effective_usage_score → eligible_for_additional_tokens / review_recommended / insufficient_evidence with numeric evidence.
  • Operational: data-quality panel + ingestion-health panel.

13.2 User dashboard (private, self-service)

  • Personal token/credit usage, remaining budget, cache-hit rate, cost trend.
  • Top token-consuming sessions (tokens, model, tier, estimated wastage) — numeric evidence, never prompt content.
  • Prompt-pattern feedback (tier mix, tool usage, retry loops, high-input/low-output) framed as coaching.
  • Actionable, non-punitive suggestions (lower-cost/Auto when sufficient, reduce context bloat/cache misses, scope large sessions).
  • Personal effectiveness summary (right-sized ratio, wastage rate, completion rate) for self-assessment before requesting more tokens.

14. Privacy, Governance & Reporting Rules

  • Exclude by default: content, response, userRequest, raw tool arguments, file contents, source-code paths. Agent debug logs collect only an allow-listed set of event categories, statuses, timestamps, durations, counts.
  • Pseudonymity & access: prefer pseudonymous IDs and aggregate reporting; identifiable drill-down requires an authorized admin with a documented business purpose (audited).
  • Consent lifecycle: opt-in/opt-out state + timestamp; consent before collection; withdrawal stops collection; erasure keyed by ACF2 ID; Teams org attributes refreshed on a defined cadence.
  • Pre-rollout statements: retention, consent/notice, access control, regional/legal review; AWS workload-account owner, approved region, service choices, IAM roles, encryption-key ownership.
  • Framing: separate model-selection coaching from employee-performance judgment; never infer intent, productivity, or personal use from prompts. Clearly distinguish observed telemetry, calculated estimates, and heuristic recommendations.
